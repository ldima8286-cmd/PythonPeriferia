# Periferia с нуля: инструкция для чайников

Эта страница — для тех, кто никогда не пользовался Periferia и, может быть,
не очень дружит с терминалом. Всё по шагам, каждую команду можно скопировать.
Если что-то пойдёт не так — в конце есть разбор частых проблем.

Технические подробности здесь не нужны. Если захочется глубже — в конце есть
ссылки.

## Что это такое и зачем

Обычно микрофон в Discord, Zoom или OBS включён всегда: либо тебя слышно
постоянно, либо ты жмёшь кнопку «Mute» руками. Periferia делает как в рации:
**пока держишь выбранную клавишу — микрофон открыт, отпустил — закрыт**. И не
важно, какая это программа, потому что Periferia управляет звуком всей системы
сразу.

Работает это через маленький виртуальный микрофон. Приложения думают, что это
твой обычный микрофон, а Periferia потихоньку закрывает и открывает его. Твой
настоящий микрофон при этом не трогается.

## Что понадобится

- Linux со звуком на **PipeWire**. Проверить: открой терминал и введи

  ```bash
  pactl info | grep "Server Name"
  ```

  Если в ответе есть слово `PipeWire` — всё хорошо. Если `pulseaudio` —
  Periferia не подойдёт (нужен PipeWire).
- Клавиатура — любая.
- Для смены профилей по окнам — рабочий стол KDE (KWin). Для самого
  push-to-talk это не обязательно.

## Шаг 1. Установка

Выбери **один** способ.

### Самый простой — один файл

1. Скачай `Periferia-<версия>-x86_64.AppImage`.
2. В терминале, в папке со скачанным файлом:

   ```bash
   chmod +x Periferia-*.AppImage
   ./Periferia-*.AppImage
   ```

   Ничего в систему не устанавливается. Хочешь иконку в меню — скопируй файл в
   папку `~/Applications`, и он появится сам.

### Flatpak

```bash
flatpak run org.periferia.Periferia
```

(Нужен установленный Flatpak-бандл. Локальная сборка — в основном README.)

### Arch Linux (AUR)

```bash
cd packaging/aur
makepkg -si
```

### Из исходников (для остальных)

```bash
git clone https://github.com/ldima8286-cmd/PythonPeriferia
cd PythonPeriferia
bash scripts/dev-setup.sh
source .venv/bin/activate
```

Во всех примерах ниже команда `periferia` — это установленная программа.

## Шаг 2. Проверка, что всё на месте

```bash
periferia check
```

Эта команда смотрит, всё ли готово: читаются ли клавиши, виден ли звук, нет ли
чего-то не хватающего. Прочитай вывод. Если что-то помечено как проблема с
доступом к клавиатуре — открой [udev.md](udev.md) (там одна короткая команда,
которую надо выполнить один раз).

## Шаг 3. Выбор кнопки

Надо решить, какой клавишей будешь «говорить». Periferia умеет показать её код:

```bash
periferia pick-key
```

Нажми ту клавишу, которой хочешь пользоваться. Команда покажет что-то вроде
`KEY_Y`. **Запиши это название** — оно понадобится на следующем шаге.

Советы по выбору клавиши:

- Удобно: что-то рядом с левой рукой, например `KEY_Y`, `KEY_U`, `KEY_H`,
  `KEY_N` или `KEY_GRAVE` (клавиша над Tab).
- Плохо: `KEY_W`, `KEY_A`, `KEY_S`, `KEY_D` — это кнопки движения в играх.
- Нельзя: ничего из системных сочетаний вроде печати экрана.
- Можно даже кнопку мыши, но это отдельная настройка (см. основной README).

## Шаг 4. Создание настроек

```bash
periferia init-config
```

Эта команда создаст файл `~/.config/periferia/config.yaml`. Открой его
текстовым редактором (например, `nano ~/.config/periferia/config.yaml`) и
найди строку:

```yaml
ptt_key: auto
```

Замени `auto` на код из шага 3, например:

```yaml
ptt_key: KEY_Y
```

Сохрани файл. Всё остальное в конфиге можно не трогать — значения по умолчанию
разумные.

## Шаг 5. Переключить приложения на виртуальный микрофон

Теперь надо сказать системе (и приложениям), что микрофон — это `PeriferiaMic`:

```bash
periferia set-default
```

Дополнительно в самих приложениях (Discord, Zoom, OBS, браузере) в настройках
микрофона выбери **`PeriferiaMic`**. Обычно после `set-default` он уже выбран по
умолчанию, но проверить стоит.

> Если забыть этот шаг, push-to-talk будет включаться, но тебя никто не услышит:
> приложение всё ещё слушает настоящий микрофон, а его Periferia не закрывает.

## Шаг 6. Запуск

Нажми клавишу — микрофон открылся, отпустил — закрылся. Запустить можно так:

```bash
periferia-daemon
```

В терминале это видно, и остановить можно `Ctrl+C`. Чтобы Periferia работала
сама, без терминала, поставь службу:

```bash
periferia install-service
```

Если очень долго держать клавишу, микрофон **зафиксируется** открытым (полезно,
когда нужны обе руки). После этого нажми клавишу ещё раз — микрофон закроется.
По умолчанию это выключено; включает параметр `latch_ms` в конфиге.

## Шаг 7. Убедиться, что работает

Открой статус:

```bash
periferia status
```

Ты увидишь, открыт микрофон сейчас или закрыт. Нажми и подержи свою клавишу —
статус должен меняться на `OPEN`, а после отпускания — обратно на закрытый
(возможно, с небольшой задержкой).

Если хочется полной проверки:

```bash
periferia tui
```

Это самопроверка в терминале. Она попросит тебя нажать и подержать клавишу — это
и есть настоящий тест push-to-talk. Перед запуском лучше остановить службу:

```bash
systemctl --user stop periferia
periferia tui
```

Есть ещё `periferia gate-check` — она показывает, срабатывает ли открытие вообще,
даже если под рукой нет программы, которую можно послушать.

## Как этим пользоваться каждый день

- Запустил один раз службу — дальше просто держишь клавишу в любой программе.
- Кнопка работает одинаково во всех приложениях.
- В играх настройкам клавиши ничего не мешает: Periferia клавиатуру **только
  читает**, не перехватывает, поэтому печатать и играть можно как обычно.
- Хочешь иконку — запусти `periferia-tray` (зелёная точка = микрофон открыт).

## Если что-то не так

| Что видишь | Что делать |
| --- | --- |
| Клавиша не реагирует | `periferia check` — он пометит недоступные устройства. Чаще всего нужна настройка из [udev.md](udev.md). |
| На одной клавиатуре работает, на другой нет | Вторая клавиатура закрыта правами доступа; `periferia check` перечислит, какие узлы не удалось открыть. |
| Микрофон открывается, но тебя не слышно | Приложение смотрит на настоящий микрофон. Сделай `periferia set-default` и выбери `PeriferiaMic` в настройках самого приложения. |
| Щелчки при открытии/закрытии | В конфиге увеличь `attack_ms` и `release_ms`. |
| Клавиши всё равно печатаются в приложение | Так бывает, если клавиатуру уже перехватила другая программа; проверь `sudo fuser -v /dev/input/event5`. |
| После сбоя что-то осталось | `periferia teardown`. |
| Совсем ничего не помогает | Открой issue и приложи вывод `periferia check` и название дистрибутива и рабочего стола. |
